# Native Delta parity tests

Every one of the **25 reviewed Soothe3 cases** has a named primary test:

```text
delta_error[n, channel] = Lullaby_native_Delta[n, channel]
                        - Soothe3_native_Delta[n, channel]
```

Identical outputs produce exactly zero samples. The runner saves this signal as
`delta-error.wav`, at its original level. It renders the actual Lullaby VST3 in
Delta mode; mathematical dry-minus-wet is never substituted for native Delta.

This is a deliberately strict acceptance suite. Separate progress scores below
measure improvement while these acceptance tests are still red. Native rendering uses the
macOS offline host; the metric, adapter and harness regression tests run on
Windows, macOS and Linux in CI without either installed plugin or local WAVs.

## Run

From the repository root, with the reviewed corpus already present at
`.local/soothe3-capture/`:

```sh
python3 -m venv target/reference-venv
target/reference-venv/bin/python -m pip install numpy==2.3.4
cargo xtask bundle lullaby --release --locked
cargo build --manifest-path tools/reference-host/Cargo.toml --locked --target-dir target/reference-host
target/reference-venv/bin/python -u scripts/reference_parity.py
```

Build the candidate after each DSP or parameter change. Each run creates a new
timestamped folder in `target/reference-parity/`. `--output` selects an explicit
**new** directory; existing output is refused so old candidate audio cannot
produce a passing result. Soothe3 itself is not loaded by this runner: it reads
the previously captured references. No license service is required for the
Lullaby comparison.

```sh
# A partial diagnostic run; the default always runs all 25 cases.
target/reference-venv/bin/python -u scripts/reference_parity.py --case 06_bandlimited_saw

# List the fixed case IDs without loading a plugin.
target/reference-venv/bin/python scripts/reference_parity.py --list

# Verify the test oracle and harness without the local reference corpus.
target/reference-venv/bin/python -m unittest discover -s scripts -p 'test_parity*.py'
```

`--corpus`, `--plugin`, and `--host` select alternative paths. A bounded host
process per case isolates crashes; `--timeout` changes its default 120-second
limit. The CLI exits **1** if any acceptance/support test fails and **0** only
when the selected suite passes. A partial run is labeled `full_corpus: false`.

## Acceptance contract

[`parity_contract.json`](../scripts/reference/parity_contract.json) pins the 25
reviewed case IDs, capture metadata, WAVs, states, corpus index, and environment
with SHA-256 hashes. It is independent of the mutable capture metadata, and is
never regenerated by the test runner. Changed/missing references or additional
case directories fail. Legitimate recaptures require deliberate review and a
contract update.

Provisional primary limits are fixed across all cases:

| Measurement | Required maximum |
| --- | ---: |
| Difference-of-deltas RMS | −80 dBFS |
| Difference-of-deltas peak | −60 dBFS |
| RMS error relative to reference Delta RMS | −50 dB |

The relative limit is approximately 0.316% amplitude error. All three gates
apply both globally and **to every channel**. A truly silent reference channel
uses the absolute limits. Exact identity is reported separately from acceptable
small numerical error. Zero amplitudes have JSON `null` decibel levels, with
explicit linear zero values and status fields, not NaN or Infinity.

Each plugin is compensated only by **its own reported VST3 latency**. The primary
test compares the entire matching frame count, including lead-in, onset,
automation and decay. There is no gain fit, cross-correlation alignment, phase
correction, downmix, resampling, normalization or silence trimming. Gain and lag
estimates in reports are explanatory measurements and never alter acceptance.

Do not loosen these thresholds or tune mappings separately per case to make the
current implementation pass. A future tolerance change is a reviewable change
to the acceptance contract, rather than an automatic result of a failed test.

## Measure incremental progress

After a complete baseline run, freeze every successfully rendered baseline case
into a reusable cohort. Keep this same baseline and cohort throughout an
improvement round:

```sh
target/reference-venv/bin/python scripts/reference_parity_score.py freeze \
  target/reference-parity/round1-00-baseline \
  --output target/reference-parity/round1-cohort.json

target/reference-venv/bin/python scripts/reference_parity_score.py compare \
  target/reference-parity/round1-00-baseline \
  target/reference-parity/round1-01-routing \
  --cohort target/reference-parity/round1-cohort.json \
  --output target/reference-parity/round1-01-comparison.json
```

The progress score is the equal-case mean of
`(Delta error RMS / reference Delta RMS)^2`, computed from the original-gain
native Delta null. Lower is better; zero means an exact null. Its dB value is
`10*log10(score)`. Absolute residual RMS is the square root of the equal-case
mean squared residual RMS. Scores also retain each case's change, the worst
channel by normalized error and by absolute RMS, strict primary pass counts,
and full render coverage. A fixed `1e-12` reference RMS floor handles silent
references without nonfinite values; it does not change acceptance thresholds.

Both runs must contain every required case and match the acceptance contract.
The cohort includes **all** baseline successes, with failed baseline cases
recorded explicitly. If a candidate loses any cohort case, its aggregate score
is invalid and the comparison exits 1. Newly supported cases are reported
separately until a deliberately reviewed new round establishes another cohort;
they cannot dilute the existing score. The initial unsupported surround case
therefore remains visible as a failing acceptance test alongside the 24-case
progress score. Changed baseline measurements, partial runs, inconsistent
channel measurements and nonfinite values are rejected. No gain/lag fitting is
used and no strict test is relaxed by an improved progress score.

## Support tests and diagnostics

Each case also tests:

- **Control equivalence and parameter readback:** unavailable features and
  uncalibrated control scales are failures. Requested final values must actually
  reach the plugin, including automation and Delta monitoring.
- **Delta level:** per-channel RMS level within 0.5 dB of the reference.
- **Delta spectral shape:** per-channel frequency-band energy within 1 dB.
- **Delta timing envelope:** per-channel 10 ms windows within 1 dB. Unexpected
  energy in effectively silent reference windows fails too.
- **Wet waveform null:** the wet output uses the same strict sample-level gates.
- **Native monitoring routing:** unity wet + native Delta must reconstruct the
  input. The mixed-gain case has a separate non-unity routing assertion.

Reports locate the worst channel, sample, time window and frequencies; retain
per-channel band energies and complex phase differences at dominant reference
frequencies; and measure labeled automation/band-shape segments, onset and tail.
These distinguish magnitude, phase, timing, focus/linking and routing failures.
The primary phase-sensitive null remains decisive even when magnitudes match.

The mixed-gain case (`19`) additionally renders Lullaby at unity mix/trims with
identical DSP settings as a within-plugin basis. The reviewed Soothe3 reference
pair (`02`, `19`) establishes the following routing relation to numerical
precision:

```text
wet   = output_gain * ((1-mix)*dry + mix*wet_gain*unity_wet)
Delta = output_gain * mix * wet_gain * unity_Delta
```

For the captured 50% / +6 dB / −6 dB combination, the native Delta factor is
**0.5**. This check identifies gain-routing errors independently of the shared
detector's agreement with Soothe3. The reference relation is verified before it
is used; it is an observation for these captures, not a claim about all settings.

## Current control and feature gaps

[`parity_adapter.py`](../scripts/reference/parity_adapter.py) records fixed,
explicit exploratory conversions where the current plugins do not share a
calibrated control law. Depth and Detail now expose unitless 0–10 scales; their independently calibrated
strength/bandwidth laws still have measurable error. Unitless timing controls, frequency tilts,
band depth/Q and unlimited reduction must not be treated as equivalent merely
because their names resemble each other. These exploratory renders help
diagnose the current behavior, while their capability tests remain red until
the feature/control contract is implemented and verified.

In particular, Soothe3's unlimited maximum cut is currently represented only by
an explicitly flagged finite Lullaby limit. Its 16-channel surround reference is
attempted unchanged and fails the current mono/stereo Lullaby bus negotiation.
It stays a named failing primary test: it is never skipped, downmixed, or
fabricated from stereo renders. Initial parameter readback can verify a chosen
exploratory mapping; it cannot prove the DSP law equivalent.

Nested Lullaby band parameters have repeated display names. The host addresses
them by stable `#<VST3 parameter ID>` selectors and rejects ambiguous name-only
requests, preventing silent edits to the wrong band.

## Results and provenance

Every run includes:

- `summary.json`: all 25 primary results and supporting test outcomes.
- `tests.txt` and `junit.xml`: named failures for tools and CI consumers.
- `environment.json`, `lullaby-parameters.json`, `provenance/`: candidate bundle
  and host hashes, source snapshots including plugin/DSP code and the control
  adapter, dependency locks, reference path, Python and NumPy versions.
- `cases/<id>/report.json`: full metrics, applied parameters, capabilities and
  host metadata. Each successfully rendered case also has `lullaby-wet.wav`,
  `lullaby-delta.wav`, `wet-error.wav`, and **`delta-error.wav`**.
- Case 19 also retains its unity-basis wet/Delta renders. Unsupported renders
  have an explicit failure and host logs, rather than false output WAVs.

The oracle regression tests prove exact identity passes and that silence, gain
errors, polarity, one-sample shifts, channel swaps, local clicks, invalid shapes,
nonfinite audio, missing cases, changed checksums and unapplied controls cannot
silently pass. They also guard the mixed-gain native routing assertion. These
tests are part of public CI; the intentionally red licensed-reference suite is
run locally and keeps its audio ignored by Git.

## Parameter compatibility during parity development

Depth now spans **0–10**, rather than 0–24, and Detail spans **0–10**, rather
than 0–1. The editor labels the latter **Detail**, without a percentage. Depth is
unitless strength; Detail controls the concentration and strength of spectral
cuts, not a Q value or bandwidth in Hz. Matching the reference's labels and ranges
does not prove identical processing. The reference adapter retains explicit
uncalibrated-scale failures for both controls.

Gentle start now uses Depth 3/Detail 5 as an intentional gentle Lullaby preset;
this does not claim that Soothe3's factory default Depth is 3. Other Lullaby factory
presets inherit that new gentle base unless they specify Depth themselves.

This development change does **not** preserve the sound of earlier projects.
Stable VST parameter IDs remain: old normalized Depth automation/state is now
interpreted over 0–10 (for example an old displayed 6 at 25% becomes 2.5). Detail's
normalized positions retain their new displayed counterparts (old 0.5 becomes 5),
but its processing law has changed. Direct JSON `Settings` uses displayed units;
old Detail 0.5 means 0.5 now, and old Depth values above 10 clamp to 10. Existing
user presets should be reviewed and re-saved rather than assumed equivalent.
